# Проектные кейсы

Кейсы построены по схеме: **задача → архитектурное решение → технические сложности → результат/статус**.

## Коммерческие направления

- [Автомобильная data platform](automotive-data-platform.md) — каталог, нормализация, OEM, поколения и модификации.
- [Event analytics](event-analytics.md) — потоковая аналитика на Kafka и ClickHouse.
- [Production platform / CI/CD](platform-ci-cd.md) — Docker Swarm, Traefik, GitLab Runner, выпуск изменений.

## Собственные проекты

- [Bakery Orders](bakery-orders.md) — Laravel-система заказов для производственной пекарни.
- [FinExchange](finexchange.md) — проектирование P2P-обмена и Double-Entry Ledger на Go.

Статус каждого проекта указан отдельно: **реализовано**, **обсуждалось/разрабатывалось** или **запроектировано**. Это важно, чтобы не приписывать проектам отсутствующий production-опыт.
