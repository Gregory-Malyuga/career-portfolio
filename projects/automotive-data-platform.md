# Automotive Data Platform — импорт, нормализация и matching

**Тип:** коммерческое направление · **Компания:** Движком

## Проблема

Автомобильные товары и справочники поступают из неоднородных источников: отличаются форматы марок, моделей, индексов кузова, поколений, модификаций, OEM-номеров. Ошибки нормализации влияют на поиск, совместимость и качество каталога.

## Масштаб и результаты

- Каталог — **122 млн записей**, данные из **100+ источников** (из исходного CV).
- Модульный backend из **19 доменов**.
- По CV автоматизация matching уменьшила ручную проверку на **40%**.

## Подход

1. Приём, проверка и пакетная загрузка исходных данных.
2. Нормализация идентификаторов и атрибутов.
3. Асинхронная обработка с очередями, retry, отслеживанием прогресса и восстановлением.
4. Сопоставление автомобильных сущностей разными способами.
5. Анализ неопределённых и неоднозначных результатов; ручная проверка исключений.

## Отдельное исследование matching

Разбирал CSV с признаками: **brand/model/generation/year_from/year_to**, а также **engine_code, engine_volume, fuel, transmission, drive, body**. Проверялись три направления:

- Прямой поиск по марке и модели.
- Обратный поиск по техническим характеристикам.
- Определение по кузовному индексу (например, BMW E92).

Требовалось устранить ложные поколения, в частности не путать **E39 с римским номером поколения**, и не подменять номер поколения годами выпуска. Целевой результат — надёжное определение модификаций и прозрачный процент unresolved.

**Важно:** эксперименты с CSV/справочниками — отдельная аналитическая работа; без опубликованной валидации нельзя заявлять точность matching на всём датасете.

## Технологии

PHP/Laravel, PostgreSQL, RabbitMQ, Redis, Elasticsearch, Docker, аналитика CSV, асинхронные воркеры.
